# Implementation Plan: Hybrid Icarus Server

## Goal Description
Replicate the successful "Hybrid Cloud Architecture" from the Minecraft project, but adapted for an Icarus Dedicated Server. The system will host the compute-heavy Icarus game server locally using Docker, while proxying all public traffic through a low-cost AWS Lightsail gateway using a Fast Reverse Proxy (FRP) tunnel. This ensures DDoS protection, hides the local IP, and bypasses local NAT/port-forwarding issues.

## User Review Required
> [!IMPORTANT]
> **UDP Traffic over FRP:** Icarus relies on UDP for gameplay (Port 17777) and Steam Server Queries (Port 27015). FRP supports UDP tunneling, but we need to ensure the Lightsail firewall explicitly opens these UDP ports. 

> [!NOTE]
> **No Modpack Management:** Unlike Minecraft, Icarus doesn't require a custom client-side modpack downloader. The web dashboard will be streamlined to only show the server status (Online/Offline) and tunnel health.

## Open Questions
1. **Server Configuration:** Do you want me to expose all Icarus server variables (e.g., `SERVER_NAME`, `SERVER_PASSWORD`, `MAX_PLAYERS`) in a `local/.env` file for easy configuration?
2. **Backups:** The Minecraft version used `itzg/mc-backup`. For Icarus, we can either use a generic restic container to backup the `data/` directory or rely on the Icarus server's built-in autosaves. Shall I include a generic backup container?

## Proposed Changes

We will create a structured repository mirroring the previous project:

### Root Directory
#### [NEW] `Makefile`
A Makefile to orchestrate cloud deployment (`make cloud-deploy`), local server startup (`make local-up`), and logs (`make mc-logs` -> `make icarus-logs`).

#### [NEW] `README.md`
Documentation explaining the architecture and setup instructions.

---

### Cloud Component (`cloud/`)
#### [NEW] `cloud/main.tf`
Terraform script to deploy an AWS Lightsail instance (e.g., `ubuntu_22_04`), allocate a static IP, and open ports:
- TCP: 80, 443 (Web Dashboard)
- TCP: 7000 (FRP Tunnel), 7500 (FRP Dashboard)
- UDP: 17777 (Icarus Game Port), 27015 (Steam Query Port)

#### [NEW] `cloud/index.html.tpl` & `cloud/Caddyfile.tpl`
A responsive, dark-mode web dashboard served over HTTPS via Caddy. It will display the status of the tunnel and the game server.

#### [NEW] `cloud/terraform.tfvars.template`
Variables template for DuckDNS tokens and FRP credentials.

---

### Local Component (`local/`)
#### [NEW] `local/docker-compose.yml`
Will run two services:
1. `icarus`: Using the `mornedhels/icarus-server` Docker image. It will mount a `data/` volume for persistent world saves.
2. `frpc`: The FRP client, configured to tunnel UDP traffic to the AWS gateway.

#### [NEW] `local/.env.template`
Will hold environment variables for the Icarus server (Server Name, Password, Steam credentials if needed) and the FRP authentication token.

#### [NEW] `local/frpc.tpl` (Generated by Terraform)
Configuration file for the FRP client to connect to the AWS Gateway, forwarding UDP ports `17777` and `27015`.

## Verification Plan

### Automated Tests
- Run `terraform validate` in the `cloud/` directory to ensure syntax correctness.
- Run `docker compose config` in the `local/` directory to validate the compose file structure.

### Manual Verification
1. Run `make cloud-deploy` and verify the AWS instance provisions successfully.
2. Visit the web dashboard domain to ensure HTTPS and the status page render correctly.
3. Run `make local-up` and verify both `icarus` and `frpc` containers start without errors.
4. Attempt to connect to the Icarus server via the Steam Server Browser using the DuckDNS domain.
